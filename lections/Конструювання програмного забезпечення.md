## Zen of Python (PEP 20)

```python
>>> import this

Beautiful is better than ugly.
Explicit is better than implicit.
Simple is better than complex.
Readability counts.
Errors should never pass silently.
```

## Ключові принципи

- **Beautiful / Readability** — індентація замість `{}`
- **Explicit > Implicit** — обов'язковий `self`, явний імпорт
- **One obvious way** — довго не було `switch/case`
- **Errors never pass silently** — основа EAFP

## Duck Typing

```python
class Duck:
    def quack(self):
        print("Кря-кря!")

class Person:
    def quack(self):
        print("Імітую качку")

def make_it_quack(entity):
    entity.quack()  # isinstance() не потрібен
```

--

## Виклик

```python
make_it_quack(Duck())    # Кря-кря!
make_it_quack(Person())  # Імітую качку
```

--

## Для порівняння: Java

```java
interface Quacker {
    void quack();
}
class Duck implements Quacker {
    public void quack() {...}
}
```

У Java об'єкт має явно реалізувати інтерфейс.

## LBYL — Look Before You Leap

```python
if hasattr(entity, "quack") and callable(entity.quack):
    entity.quack()
```

--

## EAFP — Easier to Ask Forgiveness

```python
try:
    entity.quack()
except AttributeError:
    pass
```

Ідіоматичний Python. Пов'язано з "Errors should never pass silently".

## Duck Typing і протоколи

```python
class Countdown:
    def __init__(self, n):
        self.n = n
    def __iter__(self):
        return self
    def __next__(self):
        if self.n <= 0:
            raise StopIteration
        self.n -= 1
        return self.n + 1

for x in Countdown(3):
    print(x)   # 3 2 1
```

--

## Дизайн на основі протоколів

- `__iter__` / `__next__` → ітерація (`for`)
- `__len__` → `len(obj)`
- `__enter__` / `__exit__` → `with obj:`
- `__eq__` / `__lt__` → порівняння

## Правило LEGB

**L**ocal → **E**nclosing → **G**lobal → **B**uilt-in

```python
x = "global"
def outer():
    x = "enclosing"
    def inner():
        x = "local"
        print(x)     # -> "local"
    inner()
    print(x)         # -> "enclosing"
print(x)              # -> "global"
```

## nonlocal

```python
def counter():
    count = 0
    def increment():
        nonlocal count
        count += 1
        return count
    return increment

c = counter()
print(c())  # 1
print(c())  # 2
```

--

## global

```python
total = 0
def add_to_total(n):
    global total
    total += n
```

Без `nonlocal`/`global` — нова ЛОКАЛЬНА змінна замість зовнішньої.

## UnboundLocalError

```python
x = 10
def broken():
    print(x)   # UnboundLocalError!
    x = 20
```

Присвоєння будь-де в тілі функції робить ім'я ЛОКАЛЬНИМ для всієї функції відразу.

## Виправлення

```python
x = 10
def fixed():
    global x
    print(x)   # 10
    x = 20
```

## Простір імен класу

## sys.modules

```python
import sys
print(sys.modules.keys())
# усі завантажені модулі процесу
```

Крок 3 — ключ до циклічних залежностей.

## Циклічні залежності: проблема

```python
# module_a.py
import module_b
def func_a():
    return module_b.func_b()
```

```python
# module_b.py
import module_a
def func_b():
    return module_a.func_a()
```

--

## Що відбувається при `import module_a`

1. виконує `module_a.py`, реєструє частковий `module_a`
2. `import module_b` → починає `module_b.py`
3. `module_b`: `import module_a` → ВЖЕ у `sys.modules` — не виконує повторно
4. `func_a` ще не визначена? → `AttributeError` / `ImportError`

---

## Рішення 1 — відкладений імпорт

```python
def func_a():
    import module_b
    return module_b.func_b()
```

--

## Рішення 2 — реструктуризація

Спільна логіка виноситься в `common.py`, від якого залежать обидва модулі.

---

## Рішення 3 — імпорт модуля, а не імені

```python
import module_b
module_b.func_b()
```

--

## Рішення 4 — TYPE_CHECKING

```python
from typing import TYPE_CHECKING
if TYPE_CHECKING:
    import module_b
def f(b: "module_b.X"): ...
```

## `__init__` та `self`

```python
class Dog:

        self.name = name

rex = Dog("Рекс", "Вівчарка")
```

## Атрибути екземпляра vs класу

```python
class Dog:

```

## Інкапсуляція за угодою

```python
class Account:
    def __init__(self, balance):
```

## Перевантаження оператора `+`

```python
class Vector:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __add__(self, other):
        return Vector(self.x + other.x, self.y + other.y)

v1, v2 = Vector(1, 2), Vector(3, 4)
v1 + v2   # викликає v1.__add__(v2)
```

## Для порівняння — C++

```cpp
Vector operator+(const Vector& other) const {
    return Vector{x + other.x, y + other.y};
}
```

Тут вибір оператора — на етапі компіляції. У Python — під час виконання.

## __radd__

```python
class Vector:
    def __add__(self, other):
        if not isinstance(other, Vector):
            return NotImplemented
        return Vector(self.x + other.x, self.y + other.y)

    def __radd__(self, other):
        return self.__add__(other)
```

Якщо `__add__` повертає `NotImplemented` — Python пробує `__radd__` іншого операнда.

## Порівняння об'єктів

```python
from functools import total_ordering

@total_ordering
class Money:
    def __init__(self, amount):
        self.amount = amount

    def __eq__(self, other):
        return self.amount == other.amount

    def __lt__(self, other):
        return self.amount < other.amount
```

`total_ordering` добудовує `<=`, `>`, `>=` з `__eq__` і `__lt__`.

## Протокол колекції

```python
class Deck:
    def __init__(self):
        self.cards = list(range(52))

    def __len__(self):
        return len(self.cards)

    def __getitem__(self, index):
        return self.cards[index]

    def __contains__(self, card):
        return card in self.cards
```


## property — контрольований доступ

```python
class Temperature:
    def __init__(self, celsius):
        self._celsius = celsius

    @property
    def celsius(self):
        return self._celsius

    @celsius.setter
    def celsius(self, value):
        if value < -273.15:
            raise ValueError("Нижче абсолютного нуля")
        self._celsius = value
```

--

## Виглядає як поле

```python
t = Temperature(25)
t.celsius = 30   # насправді викликає setter із валідацією
```

Можна почати з публічного поля, а `property` додати пізніше — без зміни зовнішнього коду.

## Повний протокол дескрипторів

```python
class PositiveNumber:
    def __set_name__(self, owner, name):
        self.name = "_" + name

    def __get__(self, instance, owner):
        if instance is None:
            return self
        return getattr(instance, self.name)

    def __set__(self, instance, value):
        if value <= 0:
            raise ValueError(f"{self.name} має бути додатним")
        setattr(instance, self.name, value)
```

--

## Дескриптор як атрибут класу

```python
class Product:
    price = PositiveNumber()
    quantity = PositiveNumber()

    def __init__(self, price, quantity):
        self.price = price
        self.quantity = quantity

p = Product(10, 5)
p.price = -5   # ValueError
```

`property`, `staticmethod`, `classmethod` — усі побудовані на дескрипторах.

## Функції — об'єкти першого класу

```python
def greet():
    print("Привіт!")

def loud(func):
    def wrapper():
        print("!!!")
        func()
        print("!!!")
    return wrapper

greet = loud(greet)   # ручне "декорування"
```

--

## Синтаксичний цукор `@`

```python
def loud(func):
    def wrapper(*args, **kwargs):
        print("!!!")
        result = func(*args, **kwargs)
        print("!!!")
        return result
    return wrapper

@loud
def greet(name):
    print(f"Привіт, {name}!")
```

`@loud` над `def greet` = `greet = loud(greet)`.

--

## functools.wraps

```python
from functools import wraps

def loud(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@loud
def greet(name): ...

greet.__name__   # 'greet', а не 'wrapper'
```

## Декоратор з аргументами

```python
def repeat(times):
    def decorator(func):
        def wrapper(*args, **kwargs):
            for _ in range(times):
                func(*args, **kwargs)
        return wrapper
    return decorator

@repeat(times=3)
def hello():
    print("Привіт!")
```

## Декоратор класу

```python
def singleton(cls):
    instances = {}
    def get_instance(*args, **kwargs):
        if cls not in instances:
            instances[cls] = cls(*args, **kwargs)
        return instances[cls]
    return get_instance

@singleton
class Config:
    def __init__(self):
        self.settings = {}
```

## Проблема управління ресурсами

- Файли, з'єднання, м'ютекси треба гарантовано звільняти
- Refcounting звільняє об'єкт одразу, але це не гарантія мови
- Циклічні посилання чекають на GC — момент непередбачуваний
- `__del__` для ресурсів — погана практика → потрібен явний `with`

## __enter__ / __exit__

```python
class ManagedFile:
    def __init__(self, path):
        self.path = path

    def __enter__(self):
        self.file = open(self.path, "r")
        return self.file

    def __exit__(self, exc_type, exc_value, traceback):
        self.file.close()
        return False
```

## Використання

```python
with ManagedFile("data.txt") as f:
```

## Пригнічення винятків

```python
class IgnoreZeroDivision:
    def __enter__(self):
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        return exc_type is ZeroDivisionError

with IgnoreZeroDivision():
    1 / 0
print("Продовжуємо — виняток придушено")
```

`__exit__` -> `True` = виняток "проковтнутий".

## contextlib.contextmanager

```python
from contextlib import contextmanager

@contextmanager
def managed_file(path):
    f = open(path, "r")
    try:
        yield f
    finally:
        f.close()

with managed_file("data.txt") as f:
    content = f.read()
```

До `yield` — `__enter__`, після — `__exit__`.

## Підсумок лекції

| Тема | Ключова ідея |
|---|---|
| Клас та `__init__` | Шаблон для екземплярів; `self` — посилання на об'єкт |
| Атрибути | Екземпляра (свої) vs класу (спільні) |
| Успадкування | `super()` — доступ до методів батьківського класу |
| Інкапсуляція | `_protected`/`__private` — угода й name mangling |
| Магічні методи | Оператори та протоколи мови через dunder |
| property / дескриптори | Синтаксис поля, семантика методу |
| Декоратори | Рантайм-обгортання функцій і класів через `@` |
| `with` | Явний протокол `__enter__`/`__exit__` |
